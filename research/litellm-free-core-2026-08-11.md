## 2. Enterprise tier contents + pricing page

- SSO + SCIM, OIDC/JWT auth, custom auth — enterprise. Notable: **"SSO is free for up to 5 users"** (https://docs.litellm.ai/docs/enterprise ; https://www.litellm.ai/pricing).
- Audit logs (with retention policy) — enterprise (https://docs.litellm.ai/docs/proxy/enterprise ; https://www.litellm.ai/pricing).
- Secret managers (AWS KMS, Google Secret Manager, Azure Key Vault, Hashicorp Vault) + write-key-to-secret-manager + key rotation — enterprise (https://docs.litellm.ai/docs/proxy/enterprise ; https://www.litellm.ai/features).
- Other enterprise items a B2B client would notice: IP allow-lists, JWT auth, restrict public/private routes, max request/file size enforcement, enforced required params, RBAC by key/team/org, team/org admin assignment, default-on guardrails + guardrails per key/team, custom UI branding, multi-region control plane (https://docs.litellm.ai/docs/proxy/enterprise ; https://www.litellm.ai/features ; https://www.litellm.ai/pricing).
- Enterprise support: SLAs up to 24/7 — Sev0 1h, Sev1 6h, Sev2-3 24h, security patches 72h (https://litellm.ai/enterprise).
- Pricing page (https://www.litellm.ai/pricing): OSS = "$0, free forever", self-hosted. Enterprise = annual pricing sized to "annual gateway request capacity, deployment architecture, and support needs — never per token"; no listed dollar figure; contact sales; self-hosted + air-gapped options; **30-day free trial, instant key, no credit card, no sales call** (https://litellm.ai/enterprise). Enterprise positioning: "100+ users or 10+ production AI use-cases" (https://docs.litellm.ai/docs/enterprise).
- A hosted/managed LiteLLM proxy from BerriAI exists as an option (README links "Hosted Proxy" → https://docs.litellm.ai/docs/enterprise#hosted-litellm-proxy) — details not verified beyond the link (UNVERIFIED detail).

## 3. Deployment for a serious-but-small self-hosted setup

- Official image (quickstart): `docker.litellm.ai/berriai/litellm:latest` — own registry; images cosign-signed since v1.83.0-nightly post-incident (https://docs.litellm.ai/docs/proxy/docker_quick_start ; https://docs.litellm.ai/blog/security-update-march-2026). Status of legacy `ghcr.io/berriai/litellm` tags: UNVERIFIED.
- Postgres: required for virtual keys, key/team/user management, and spend logs — compose "brings up the gateway on port 4000 and a Postgres database that stores your models, keys, and spend logs"; proxy runs DB-less for pure pass-through (docker run example without `DATABASE_URL`) (https://docs.litellm.ai/docs/proxy/docker_quick_start ; https://docs.litellm.ai/docs/proxy/virtual_keys).
- Required env: `LITELLM_MASTER_KEY` (admin key), `LITELLM_SALT_KEY` (encrypts provider keys in DB) (https://docs.litellm.ai/docs/proxy/docker_quick_start).
- Redis: needed only for multi-instance — "shares rate limit counters, router state, and the response cache across instances; without it, each instance enforces limits independently"; also buffers spend writes at ~1000+ RPS / 10+ instances to avoid DB deadlocks (https://docs.litellm.ai/docs/proxy/prod). Single-instance PoC: no Redis needed.
- Prod hardening (https://docs.litellm.ai/docs/proxy/prod): K8s — 1 Uvicorn worker per pod, scale pods horizontally; VMs — workers = vCPUs; optional `--max_requests_before_restart` worker recycling; set `database_connection_pool_limit` = MAX_DB_CONNECTIONS / (instances × workers), default 10/worker (full scale-out ≈1000 connections vs stock Postgres — warned).
- Deployment paths: docker run / docker-compose, Helm on EKS/GKE/AKS, official AWS/GCP Terraform modules; monolithic mode called "simplest to operate" (https://docs.litellm.ai/docs/proxy/deploy).
- Releases: **weekly** stable cadence; since v1.84.0 plain SemVer (minor = weekly release, patch = hotfix; `-dev.N`/`-rc.N` pre-release suffixes); recommendation: "pinning to the latest stable `1.x.x` release" (https://docs.litellm.ai/docs/proxy/release_cycle).
- Current version: GitHub "Latest" = **v1.96.0, published Aug 10, 2026** (https://github.com/BerriAI/litellm/releases/latest ; release notes dated Aug 9: https://docs.litellm.ai/release_notes/); PyPI latest = **1.96.1, uploaded 2026-08-11** (https://pypi.org/pypi/litellm/json). Older lines (1.88.x–1.95.x) received backport patches on Aug 9, 2026 (PyPI upload log) — multiple supported branches.
- Repo: ~53.8k stars; `enterprise/`, `gateway/`, `backend/`, `ui/`, helm/terraform dirs present (https://github.com/BerriAI/litellm). Docs source moved to a separate repo: https://github.com/BerriAI/litellm-docs.

## 4. License

- Dual structure in one repo. Root LICENSE: everything outside `enterprise/` is **MIT** ("Copyright (c) 2023 Berri AI"); `enterprise/` content "is licensed under the license defined in 'enterprise/LICENSE'" (https://github.com/BerriAI/litellm/blob/main/LICENSE — text verified via raw fetch).
- `enterprise/LICENSE.md` = "BerriAI Enterprise license": production use requires a paid subscription — "may only be used in production, if you… have agreed to… the Enterprise Terms" (https://github.com/BerriAI/litellm/blob/main/enterprise/LICENSE.md); dev/test use allowed without subscription; copying/distributing/selling the enterprise code is forbidden without a license.
- **Hosted/managed-service resale: no restriction on the MIT core.** MIT explicitly permits use, sublicense, and sale; there is no BUSL/Commons-Clause/SSPL-style "no managed service" term anywhere in the root LICENSE. The only resale prohibition applies to the `enterprise/` directory code. (Verified against full LICENSE + enterprise/LICENSE.md text; not legal advice.)
- Practical implication: offering the free self-hosted proxy to third-party clients as a managed gateway is license-permitted, as long as no `enterprise/`-directory features / license-key features are enabled in production.

## 5. 2026 changes that alter the picture

- **March 2026 PyPI supply-chain attack (major):** litellm **1.82.7 and 1.82.8** compromised, live March 24, 2026 (~40 min before PyPI quarantine); payload harvested env vars, SSH keys, cloud creds, K8s tokens, DB passwords and exfiltrated to `models.litellm[.]cloud`; part of the broader "TeamPCP" campaign (also hit telnyx 4.87.1/4.87.2) (official: https://docs.litellm.ai/blog/security-update-march-2026 ; independent: https://securitylabs.datadoghq.com/articles/litellm-compromised-pypi-teampcp-supply-chain-campaign/ ; https://www.trendmicro.com/en_us/research/26/c/inside-litellm-supply-chain-compromise.html). Response: v1.83.0 rebuilt via new CI/CD, cosign image signing, Mandiant forensics, maintainer credential rotation.
- **April 2026 CVE cluster:** CVE-2026-35030 (critical, JWT/OIDC auth bypass via cache collision; only if `enable_jwt_auth: true`; fixed v1.83.0), CVE-2026-35029 (high, `/config/update` privilege escalation → RCE risk; fixed v1.83.0), GHSA-69x8-hrgq-fjj8 (high, unsalted SHA-256 password hashes + pass-the-hash login; fixed v1.83.0) (https://docs.litellm.ai/blog/security-hardening-april-2026). Bug bounty launched Apr 3, 2026; third-party audit by Veria Labs ongoing (same URL).
- **CVE-2026-42208:** SQL injection in the API-key verification path (Authorization header), affected v1.81.16–v1.83.6, fixed **v1.83.10-stable** (Apr 29, 2026) (https://docs.litellm.ai/blog/cve-2026-42208-litellm-proxy-sql-injection); exploited in the wild within ~36h of disclosure (https://thehackernews.com/2026/04/litellm-cve-2026-42208-sql-injection.html ; https://www.sysdig.com/blog/cve-2026-42208-targeted-sql-injection-against-litellms-authentication-path-discovered-36-hours-following-vulnerability-disclosure).
- **CVE-2026-42271:** authenticated command injection via MCP preview endpoints (`/mcp-rest/test/*`), affected 1.74.2–1.83.6, fixed 1.83.7, disclosed May 8, 2026; SentinelOne scores CVSS 8.7 / "no known exploits" (https://www.sentinelone.com/vulnerability-database/cve-2026-42271/) while CSA reports active exploitation (https://labs.cloudsecurityalliance.org/research/csa-research-note-litellm-cve-2026-42271-ai-gateway-exploita/) — conflicting exploitation claims; a blog's "CVSS 10.0" figure is UNVERIFIED.
- PoC takeaway from the above: anything ≥ v1.84.0 (current 1.96.x) post-dates all fixes; pin exact versions and verify image signatures.
- **Rust migration (in progress, not breaking):** official announcement "Migrating LiteLLM to Rust" — hot path (transforms, streaming, routing, token counting) moving to a Rust core; early beta, **opt-in per model (`rust: true`), off by default**, automatic Python fallback; claims ~15x throughput (453→6,782 RPS) and 11x less memory; Python keeps auth/config/logging/spend for now; roadmap: OCR Aug 15, `/chat/completions`+`/messages` Sep 1, router Sep 15, full server Dec 1, 2026; "not a v2… zero breaking changes" claimed, same config.yaml/DB (https://docs.litellm.ai/blog/litellm-rust-launch ; https://docs.litellm.ai/docs/proxy/rust_gateway).
- Versioning/packaging change: from v1.84.0, `-stable` suffix dropped; weekly minor releases, patches = hotfixes (https://docs.litellm.ai/docs/proxy/release_cycle). v1.96.0 gated mock-testing params behind an off-by-default config flag — minor behavioral change (https://docs.litellm.ai/release_notes/).
- **Pricing:** no 2026 price change found; still $0 OSS + custom-quoted annual enterprise, 30-day trial (https://www.litellm.ai/pricing). Notable liberalization vs 2025: SSO free ≤5 users; Prometheus metrics now in free tier (https://docs.litellm.ai/docs/enterprise ; https://www.litellm.ai/pricing).
- **Company:** no acquisition or new round found. Dealroom (pub. ~Aug 6, 2026) reports **$7M ARR**, recaps $1.6M seed (Y Combinator, Gravity Fund, Pioneer Fund), customers incl. NASA, Adobe, Netflix, Stripe, Nvidia — single-source, UNVERIFIED (https://app.dealroom.co/news/feed/litellm-raises-1-6m-seed-funding-amid-security-challenges-hits-7m-arr ; profile: https://pitchbook.com/profiles/company/520687-72).
